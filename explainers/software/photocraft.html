software · PhotoCraft · Case study

378k lines in ten days. What did it buy?

PhotoCraft is an open-source, pure-Rust reimplementation of Photoshop. Its second commit is titled “one-shot” and adds 42,000 lines. Ten days later it had ~378,000 lines of Rust, 1,089 commits, eight releases and 36,000 GitHub stars — with more than a thousand commits carrying an AI co-author trailer. It is the clearest public look yet at what agent-built software looks like at scale: real architecture, real tests, an unusually honest roadmap — and, by its own measurement, well under half of Photoshop. This leaf reads it as a case study, not a product pitch.

Agent-built at scale Rust · egui · wgpu · WASM MIT / Apache-2.0 Early alpha
01 · What it is

A Photoshop-shaped editor, written only in Rust.

PhotoCraft (github.com/storytold/photocraft) is a native raster image editor whose stated goal is 1:1 Photoshop parity — same menus, shortcuts, behaviour and file fidelity — with every feature drivable by agents. It ships under the ArtCraft brand as one of a planned family of “Craft” apps, dual-licensed MIT or Apache-2.0, and runs on macOS, Windows, Linux, FreeBSD and the browser.

  • No web shell. The desktop app is native egui/eframe on wgpu (Metal, Vulkan, DX12). The web build is the same Rust compiled to WebAssembly — no Electron, no Tauri, no JavaScript UI.
  • Real document model. Layers, masks, adjustment layers, layer styles, live type, vector shapes, smart objects with smart filters, a brush engine with pen pressure, colour management through ICC profiles, 8/16/32-bit and non-RGB modes.
  • Real files. Layered PSD open and save, plus TIFF, EXR, HEIF, several camera RAW formats and Paint.NET import.
  • Everything is a command. Every user action is a registered engine command with an id and parameter docs, dispatched identically from the menus, a headless CLI, a JSON control channel and an MCP server.

Velocity is not maturity

Lines of code and commit counts measure output, not correctness. The project says so itself: most post-release fixes “passed our tests but have not yet been validated by users”, and its first public users found 214 broken shortcuts, an immovable crop frame and panels resizing themselves — all of which counted as “live” in the menu-parity report. Agents compress the time to a plausible feature; they don't compress the time it takes real users to find out whether it works.

03 · The harness that held it together

The transferable part is AGENTS.md, not the editor.

Hundreds of agent commits a day would normally produce mush. What keeps this codebase coherent is a set of rules the agents read first — and, more importantly, tooling that enforces them whether or not the agent remembered.

Architecture

Enforced layering

Crates sit in layers L0–L6 (geometry and pixels up to the UI shell). A crate may depend only on lower layers, and cargo xtask layers fails the build if one doesn't. Nothing below the UI may touch egui.

Reliability

Never panic, by lint

Production code may not unwrap, expect, panic! or index unchecked — clippy denies it on every crate. A panic_hunt test fuzzes every command with hostile parameters. unsafe is forbidden except in one isolated tablet-input crate.

Fidelity

Corpus oracles with floors

PSD rendering is checked against Photoshop-authored files and public corpora (psd-tools, ag-psd, PngSuite). Each has a pass-count floor in the test suite: raise it, never lower it.

Portability

WASM on every PR

Every engine layer must compile for wasm32, and CI checks the browser build and its size budget on each pull request. The web build can't silently rot.

Honesty

A generated scorecard

cargo xtask scorecard regenerates performance budgets, corpus floors, per-area checklists and a count of settings that do nothing. CI fails if the committed copy is stale. Agents are told to prefer it to estimates.

Interface

One seam for everything

New behaviour must be an engine command with id, label, menu path, shortcut, params doc and tests. The UI stays thin, so agents can't hide logic in widgets that the CLI and MCP can't reach.

The lesson for your own repos

None of this is exotic — it's the agent-legible codebase and verify-or-it's-a-prompt discipline from this branch, applied hard. The pattern worth copying: every rule that matters is a failing check, not a sentence. Prose in AGENTS.md tells the agent what good looks like; the layering check, the lints, the corpus floors and the scorecard diff are what stop it shipping anything else.

Credit where it's due

Most projects with 36k stars in ten days would let the stars speak. This one publishes the number of settings that do nothing, the scenarios that blow their budget, and the admission that “our tests miss what users hit”. A self-measuring, self-critical roadmap is the second transferable lesson: when agents can generate features faster than anyone can check them, the scorecard is what stops the menu count from becoming the story.

05 · Built for agents

An image editor you can drive over MCP.

Because every action is an engine command, the same registry is exposed four ways: menus, a headless CLI (photocraft-cli: convert, info, run, batch), a JSON control channel to a running app, and an MCP server.

Headless MCP session, filesystem scoped to one folder (from docs/mcp.md) 
# without a root, the server has no filesystem authority at all
photocraft-cli mcp \
  --automation-read-root  /work/project \
  --automation-write-root /work/project

# tools: command_list, command_run, command_batch, doc_inspect,
#        render_preview, ui_inspect, ui_screenshot (bridge mode)

The design choices are sensible: read and write roots are separate and opt-in, unknown tool arguments are rejected before execution, a worker panic becomes a tool error rather than a dead session, and render_preview returns a bounded PNG so an agent can look at its own work. command_batch records one history step per command — it is not an atomic transaction, so a failed step mid-batch leaves earlier steps applied.

This is the genuinely new part. Scriptable image editing isn't new (ImageMagick, GIMP's Script-Fu, Photoshop's own ExtendScript and UXP), but a layered, PSD-aware editor with a first-class MCP surface means an agent can open a designer's layered file, change a type layer, swap a smart object and export variants — and show you a preview of each.

06 · Risks & open questions

What to weigh before you depend on it.

Read these first

  • Review debt. Hundreds of agent commits a day can't all get careful human review. The gates catch crashes, layering and regressions on the corpus; they don't catch a feature that's subtly wrong in a way no test encodes. Expect a long tail of behaviour bugs.
  • Not fully open in practice. AGENTS.md points contributors at a shared standards repo, craftrules, that “is not public” — outside contributors must ask a maintainer for the rules that govern their own PRs. The code is open-source; the process isn't entirely.
  • Trademark and IP exposure. It positions itself as a “reimplementation of Adobe Photoshop”, mirrors the menu structure, imports Photoshop .kys shortcut sets and adopts an installed Photoshop's live set on first launch. The clean-room rules are explicit (behaviour and public specs only, no copied code or assets), and US case law such as Lotus v. Borland (1st Cir. 1995) has treated menu hierarchies as uncopyrightable — but leaning on a competitor's name is the kind of thing that draws legal attention. Not legal advice; watch for changes in naming.
  • Hype-driven attention. 36k stars in ten days measures launch reach, not adoption. 557 open issues and PRs on day ten is a triage load that has to be sustained after the novelty fades.
  • Bus factor and funding. One company's org, one brand family. Read the governance and release cadence again in six months before building a workflow on top of it.
07 · Decision guide

Use it for automation and study. Not yet for production retouching.

Use it whenSkip it when
You want an agent to drive layered image edits — batch variants, type swaps, exports — through MCP or a CLI, on your own machine.Client deliverables depend on pixel-exact PSD fidelity with complex layouts, effects or smart filters.
You need a free, offline, cross-platform layered editor for light work, teaching or a browser-delivered tool.The team lives on generative fill, Adobe libraries, actions (.atn) or third-party .8BF plug-ins.
You're studying how to run an agent-built codebase — the AGENTS.md, the xtask gates, the scorecard.You need stable behaviour across months: v0.x with near-daily releases will move under you.
You'd embed a Rust imaging engine (PSD, colour management, compositor) in your own product, under a permissive licence.You need a vendor to call when it breaks.
08 · South African context

Licence-free, offline — and a lesson in method.

Where it lands here

For SA studios, schools and small agencies paying dollar-priced creative subscriptions, a permissive, offline editor that runs in a browser tab is worth tracking — but at today's PSD fidelity it complements Photoshop rather than replacing it, especially where files go back and forth with agencies abroad. The nearer-term fit is automation: retailers and e-commerce teams generating catalogue and promo variants from a layered template, run locally with no image data leaving the building (useful when POPIA questions come up about third-party processing). The bigger takeaway isn't the editor at all. It's proof that a small team with agents and hard, automated gates can stand up a serious codebase fast — and that the scorecard, not the commit count, is what tells you whether it's any good.
