Cartesia.

The vendor that picked one number and optimised everything around it: time to first audio. sonic-3.5 is the current flagship, ink-whisper handles transcription, and there is now a hosted agent runtime with phone numbers, call recordings and scored metrics. This leaf covers what the API actually exposes, the telephony path that makes it worth the switch, the 44-language list and what is missing from it, and the cases where latency is simply not the constraint you have.

Real-time TTS Vendor explainer Hot · quarterly review
01 · What it is

A speech API built around one constraint.

Most voice vendors sell breadth. Cartesia sells the gap between the last word your LLM emits and the first byte of audio your caller hears — and then builds the rest of the product to protect it.

Cartesia is a text-to-speech company whose product decisions all read the same way. The API offers raw PCM as a first-class container, not an afterthought. It exposes a websocket where you stream transcript fragments in as your LLM generates them, so synthesis starts before the sentence is finished. It ships pcm_mulaw and pcm_alaw encodings at 8 kHz, which is only useful if you are putting audio on a phone line. None of that is for someone making an audiobook.

The flagship is sonic-3.5, with sonic-3 still available and dated pins (sonic-3.5-2026-05-04, sonic-3-2026-01-12, sonic-3-2025-10-27) for anyone who needs a voice to stop changing under them. There is a sonic-latest alias, which is convenient and a bad idea in production for exactly that reason.

Since the agent runtime landed, Cartesia is no longer only a model vendor. The same API now lists agents, attaches phone numbers, retrieves call transcripts and audio, and scores calls against metrics you define. That moves it into the same bracket as ElevenAgents and Vapi — worth knowing before you assume you still need an orchestration layer on top.

02 · What the API exposes

The surface, honestly.

Taken from the published SDK surface rather than the marketing site. Everything below is an endpoint you can call today.

SurfaceEndpointsWhat it is for
TTS/tts/bytes, /tts/sse, websocket, /infill/bytesSynthesis. Bytes for one-shot, SSE and websocket for streaming, infill to regenerate a span inside existing audio without redoing the whole clip.
STT/stt plus two websocket modesTranscription on ink-whisper. The websocket comes in auto-finalize (the server decides when a turn ended) and manual-finalize (you decide) — the distinction that matters for barge-in.
Voice changer/voice-changer/bytes, /voice-changer/sseSpeech-to-speech. Keeps the delivery, swaps the speaker. Dubbing, anonymisation, accessibility.
Voices/voices, /voices/clone, /voices/localize, /accentsCatalogue, cloning, and an accent system: a published accent catalogue (en-US → General American English and so on) with a localise call that re-points an existing voice at another accent.
Agents/agents, /agents/calls, /agents/metrics, /agents/deploymentsThe hosted runtime. Agent templates, attached phone numbers, call transcripts, downloadable call audio, custom metrics with exportable results, and deployment history.
Fine-tunes/fine-tunes, /datasetsTrain a voice on your own dataset and list the voices it produced. Dataset file upload is part of the same surface.
Pronunciation/pronunciation-dictsPer-account dictionaries. The thing you reach for when a product name, a surname, or Mpumalanga comes out wrong and prompt-fiddling will not fix it.
Access tokens/access-tokenShort-lived tokens so a browser or handset can stream directly without carrying your API key.

The two knobs worth knowing

Output format. Container is raw, wav or mp3; raw encodings are pcm_f32le, pcm_s16le, pcm_mulaw and pcm_alaw. For a phone line you want raw + pcm_mulaw + 8000 Hz and nothing else — asking for 44.1 kHz MP3 and downsampling in your own code throws away the latency you came for.

Speed. model_speed is a three-position enum — slow, normal, fast — not a float multiplier. If you need fine-grained pacing, this is not the API for it.

03 · Latency, carefully

The number is real. It is also not your number.

Cartesia’s sub-100ms claim is a model-latency figure measured under the vendor’s own conditions. It is a genuine engineering result and it is not what your caller experiences.

Treat any vendor latency figure as the floor of one component. What a caller hears is the sum of: the audio getting from the handset to your STT, the transcription settling enough to be acted on, your LLM producing its first tokens, the synthesis starting, and the audio travelling back. Synthesis is usually the smallest term in that sum, and Cartesia optimises the smallest term.

This is not an argument against Cartesia — it is an argument for measuring the right thing. If your LLM takes 600ms to first token, moving from a 250ms TTS to a 90ms TTS changes your round trip by a fifth and your user’s experience by very little. Fix the dominant term first, then come back and collect the speech win.

Where it does change the experience: barge-in. When a caller interrupts, the system has to stop talking, finalise a partial transcript, and respond. That path runs several times per call and the speech components are proportionally much larger in it. Cartesia’s manual-finalize websocket exists precisely so you can control that moment rather than wait for a server-side timeout.

Measure this before you choose

Instrument four timestamps on one real call, over the network your users are actually on: last caller word → final transcript, final transcript → first LLM token, first LLM token → first audio byte, first audio byte → audible playback. Then pick a vendor. Nearly every voice-agent latency complaint we have seen traced back to the second or fourth interval, not the third.

04 · Languages

44 languages. Count what is missing.

The API’s supported-language list is published and finite, which makes it easy to check instead of trusting a “40+” headline.

The list runs 44 codes: the major European languages, Mandarin, Japanese, Korean, Arabic, Hebrew, Turkish, Vietnamese, Thai, Indonesian, Malay, Tagalog, Georgian, and an unusually deep Indian-language block — Hindi, Bengali, Tamil, Telugu, Gujarati, Kannada, Malayalam, Marathi, Punjabi, Odia and Urdu.

There is not one African language in it. No Afrikaans, no isiZulu, no isiXhosa, no Swahili. For South African delivery that is the single most important fact on this page, and it is not visible from a “44 languages” badge.

What you can do is English with an accent. The accent catalogue is a real API surface — GET /accents returns ids, locales and whether each one can be targeted by POST /voices/localize — so South African English is addressable to the extent the catalogue carries it. Audition it against real speakers before you commit; accent coverage for en-ZA is thinner than for US or UK English across every vendor in this band, Cartesia included.

Do not sell what the enum does not contain

If a client brief says “the IVR must answer in isiZulu”, Cartesia cannot do it and no amount of prompting changes that. Say so in the scoping call. The options are a specialist SA vendor, a custom model, or an honest conversation about English-plus-Afrikaans as phase one — not a demo that quietly ships US English with a hopeful accent prompt.

05 · Pricing reality

Credits, and the questions to ask.

Cartesia bills from a credit pool on tiered monthly plans. We are not quoting figures on this leaf, and that is deliberate.

Voice pricing moves faster than this leaf’s review cadence, and a stale rand figure is worse than no figure. Read the vendor’s own pricing page, then interrogate it on the four axes that actually decide your bill:

What is a credit? Characters and bytes are not the same unit. A vendor that bills per UTF-8 byte charges you more for Afrikaans diacritics and considerably more for any non-Latin script than a per-character vendor does. Ask which it is and test with your own text.

Do credits expire? A monthly pool that resets punishes spiky workloads. If your volume arrives in two campaign weeks a quarter, pay-as-you-go may beat a plan with a larger notional allowance.

Is the agent runtime billed separately? Hosted agents, attached phone numbers and call recording are a different cost line from synthesis, and telephony minutes are usually a third. Price the whole call, not the TTS.

What does FX do to it? Plans are USD-denominated. For a South African client that is unhedged exposure on a recurring line item, and it belongs in the proposal as a stated assumption with a review trigger — not as a rand number that quietly goes wrong.

06 · Decision guide

When to use Cartesia — and when to skip.

It is a specialist. That is the whole point, and it is also the reason it is the wrong default for most content work.

Use Cartesia if…

Latency is the constraint

  • You are building a real-time voice agent and have already measured the round trip
  • You need telephony-native output — pcm_mulaw at 8 kHz, straight onto the line
  • Barge-in quality matters and you want to control turn finalisation yourself
  • You want one vendor for STT and TTS on the same latency budget
  • You want a hosted agent runtime with call metrics without adding an orchestration vendor
  • You need pinned model versions so a voice does not drift mid-contract
Skip Cartesia if…

Latency is not your problem

  • You need any African language — it is not in the API, full stop
  • The work is long-form — audiobooks, narration, e-learning. Nobody waits 90ms for chapter two; buy expressiveness instead
  • You need emotion as a signal you can read, not just a tag you set — that is Hume
  • You want breadth on one invoice — dubbing, music, sound effects. ElevenLabs does more, competently
  • You need in-country or on-premises inference for a data-residency requirement — this is a hosted API
  • Your dominant latency term is the LLM, which it usually is. Fix that first
07 · South African context

What lands in SA.

Distance is part of your latency budget. Cartesia is a hosted US-centric API. From Johannesburg you are adding real round-trip time to every request before the model does anything, and that tax applies to the component Cartesia optimised. A 90ms model behind 180ms of transit is a 270ms component. Measure from where your users are, not from a laptop on a VPN.

POPIA and voice as personal information. A recording of someone’s voice is personal information, and a voice clone is personal information about an identifiable person. Sending call audio to a US API is a cross-border transfer under section 72 of POPIA and needs a lawful basis — consent, or an adequacy or contractual route. The agent runtime stores call transcripts and downloadable call audio on the vendor’s side, which widens that footprint rather than narrowing it. Decide retention deliberately and write it into the operator agreement.

Consent for cloning. Fine-tuning a voice on a staff member, a client, or a public figure needs documented, specific consent, and the responsibility sits with whoever commissions the clone, not the vendor. Keep the consent artefact with the dataset.

FX on a recurring line. USD-denominated credits on a monthly plan are an unhedged recurring cost for a rand-funded client. Put it in the proposal as an assumption with a stated review point.

The honest read. For an English-language SA voice agent where response pacing is the product — collections, bookings, triage — Cartesia is a sound choice and the telephony path is better thought through than most. For anything multilingual in South African terms, it is not a candidate.
