tech/frappe · Drive & Suite · Skill Leaf

Files, docs and mail
on your own bench.

Frappe Drive is self-hosted file storage and sharing with a collaborative document editor. The thing to know before you plan anything around it: the standalone Drive app is archived. It now ships inside Frappe Suite, one app carrying seven products — Drive, Writer, Sheets, Slides, Meet, Mail and Calendar. The migration from standalone to Suite is destructive if you get the order wrong, so read section 04 before you touch a client site.

01 · What it is

The Google Workspace shape, self-hosted.

Drive is two things in one app. The file manager does multi-part uploads for large files, folder uploads that keep your structure, in-browser previews, video streaming straight from the server, search across your files and files shared with you, per-file activity logs covering permission and metadata changes, and sharing with individual users, groups, everyone on the site, or the public. Guest users get limited, controlled access. Storage is either pooled across all users or quota'd per user. The editor, Writer, does real-time collaborative documents with inline annotations you can resolve and reply to, manual versioning alongside automatic versioning, and .docx import.

Underneath: the Frappe Framework for database, auth, permissions and realtime; Frappe UI for the interface; TipTap over ProseMirror for the editor; and Yjs, a CRDT, for the actual concurrent editing and annotation sync. That last choice is why collaborative editing behaves sensibly rather than last-write-wins.

Frappe Suite wraps Drive together with Writer, Sheets (collaborative spreadsheets, with a Hocuspocus collaboration server), Slides, Meet (group video over a mediasoup WebRTC SFU), Mail and Calendar. One app, one install, seven surfaces, AGPLv3. For a consultancy the appeal is obvious: a client who wants off a per-seat productivity subscription gets files, documents, spreadsheets, mail and calls on infrastructure they already run.

Read this before planning a Drive install

The frappe/drive repository carries an archive notice at the top of its README: Drive is archived and is now part of Suite. The repository still resolves and the code is still there, so an existing install keeps working and the documentation is still useful — but it is not where new work happens. Treat frappe/drive as reference and frappe/suite as the thing you actually install. This leaf keeps the drive route because that is what the ecosystem still calls the product.

Seven products, one app.

Mail is not a mail server, and that is the right call

Suite does not run or administer a mail server itself. The servers are Stalwart clusters managed by a separate suite_cloud app, and a Suite site is one tenant of a cluster. End users read and send straight against the cluster over JMAP with a per-account app password, so Suite only needs the cluster's server_url. Every administrative change — domains, accounts, passwords, groups, mailing lists — goes through Suite Cloud's site API, which checks that the site owns what it is touching. The site never holds cluster admin credentials. That separation is a sound security design and also a hard constraint: Mail and Calendar are fully usable with just a JMAP server, but account creation, signup and the Admin Dashboard require Suite Cloud, and without it those endpoints refuse outright.

03 · How it works

Install, and the five values Mail needs.

Suite installs like any Frappe app. Mail is the only part with configuration you cannot guess.

# Fresh install on a bench
bench get-app https://github.com/frappe/suite
bench new-site suite.localhost --install-app suite
bench start

# Production frontend build
bench build --app suite
# The five connection values a Mail-enabled site carries.
# Frappe Cloud writes these into site_config.json when it registers the site;
# on a self-managed site the Settings doctypes override them.

# Mail Settings (or the "mail" key of the site config)
server_url        # the JMAP URL users connect to
verify_ssl

# Suite Settings (or top-level keys of the same name)
suite_cloud_url
suite_cloud_tenant
suite_cloud_secret

# Confirm them with "Validate Suite Cloud Credentials" on Suite Settings
# A site that deployed mail servers through Suite before the split
bench --site yoursite migrate
bench --site yoursite install-app suite_cloud

Drive's permission model is worth understanding separately

Sharing in Drive is not just "link or no link". A file or folder can be shared with named users, with groups, with everyone on the site, or published publicly — and guest users are a distinct class with limited, controlled access. Storage is either pooled across all users or allocated as a per-user quota, which is the switch that decides whether one person's video archive becomes everyone's problem. Each file carries an activity log of permission and metadata changes, which is the closest thing here to an audit trail and worth knowing exists before someone asks who shared what.

04 · Gotchas

Where it gets tricky.

The migration to Suite deletes data before it restores it

Suite ships the same modules and doctypes as the standalone apps, so it refuses to install on a site that still has any of them — the install aborts and lists the conflicts. The documented path is: back up the site with files, uninstall every standalone app (which deletes that app's data on the site), install Suite, then restore the backup, which lands in the same tables. Then remove-from-installed-apps for each old app, install-app suite, migrate. Every step is reversible only from that backup. Do it on a clone first, and never on a Friday.

Meet and Sheets each need a process you have to run

Meet's group video depends on a mediasoup SFU, and Sheets' realtime editing on a Hocuspocus server. These are not Python workers inside the bench — they are separate services with their own ports, process supervision and, for WebRTC, firewall and NAT considerations. On Frappe Cloud that is someone else's problem. Self-hosting Suite for the video is a materially bigger job than self-hosting it for the files.

Mail's admin half is gated on an app you may not have

Without suite_cloud installed and its three credentials valid, the Admin Dashboard is hidden from admins, its routes bounce back to the mailbox, and every endpoint in the admin API refuses. Users with existing accounts can still read and send. If your plan was "self-host Suite and administer mail from the dashboard", check that assumption early.

You are now the backup strategy for everyone's files

Replacing a hosted drive means inheriting what the vendor was quietly doing: versioned backups, cross-region durability, restore on request after someone deletes a folder. Drive gives you per-document versioning in Writer and whatever you configure at the bench and storage layer — nothing more. Decide the backup, retention and restore story before migrating a client's files, and test a restore. An untested backup of a company's document store is not a backup.

Previews and streaming are server work

In-browser previews and server-side video streaming are genuinely useful and genuinely load-bearing on CPU, disk and bandwidth. A bench sized for an ERPNext workload will not be sized for a team streaming video out of it. Size the box for the file workload, not the database one.

05 · Decision guide

Use it for, skip it for.

Use Drive / Suite when

  • Documents must stay on infrastructure you control, and that requirement is firm enough to pay for in effort.
  • You are already running Frappe and want file storage with the same users, groups and permissions as the business system.
  • The need is files, documents and spreadsheets — the parts that work with the fewest extra services.
  • A per-seat productivity subscription in dollars is a line item the client wants gone and they accept the operational trade.
  • You want collaborative editing with real conflict resolution rather than a shared folder and a naming convention.

Skip Drive / Suite when

  • Nobody will own backups, restores and capacity. This is infrastructure, not an app you install and forget.
  • You need the group video to be reliable from day one. Run Meet on managed hosting or keep using what works.
  • Feature parity with Google Workspace or Microsoft 365 is the expectation. It isn't close, and offline sync clients especially are not there.
  • You need enterprise document governance — DLP, legal hold, eDiscovery, retention policy enforcement, external audit trails.
  • You have an existing standalone Drive install and no appetite for a destructive-then-restore migration. Plan it properly or stay put.
  • You aren't on Frappe. The framework is the entry price and it is too high for file storage alone.
06 · South African context

Where it lands in SA delivery work.

Residency you can actually demonstrate

This is one of the few places where "the data stays in South Africa" is a simple claim rather than a careful one. A bench in a Johannesburg or Cape Town data centre, files on local disk or local object storage, no third-party service in the path for Drive and Writer — so no cross-border transfer to document under POPIA Section 72 for the document store itself. For a client whose board has asked where the contracts live, that answer is worth real operational effort. Note the asymmetry: Drive and Writer are clean, while Mail depends on a Stalwart cluster whose location you need to establish, and Frappe Cloud has no SA region.

POPIA · sharing is the risk surface, not storage

Drive can share with everyone on the site or publish publicly in two clicks, and guest users sit outside your normal user governance. A folder of HR files shared to "everyone on the site" is a POPIA problem that looks like a convenience. Three controls that matter more than the hosting decision: default new shares to named users only, review what is published publicly on a schedule rather than on an incident, and use the per-file activity log as the thing you actually read when someone asks who had access. Per-user quotas rather than a pooled pool also limit how much ends up there in the first place.

The honest cost comparison

A per-seat subscription is a predictable rand cost tracking the dollar. Self-hosted Suite swaps that for a server, bandwidth, storage growth, and a person who maintains it — and SA bandwidth and storage are not free, especially for the video and preview workload. The migration itself is a project. Where this trade is clearly good: residency is a requirement, the team is large enough that per-seat pricing bites, and someone competent already runs the bench. Where it isn't: a ten-person firm with no sysadmin, chasing a subscription saving they will spend twice over in downtime.
