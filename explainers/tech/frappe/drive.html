tech/frappe · Drive · Skill Leaf

File storage you own.
Still in beta.

Frappe Drive is an open-source file storage, sharing and collaboration platform on the Frappe Framework — a file manager plus a real-time collaborative document editor, on infrastructure you choose. The project labels it beta and advises taking backups in production use. That caveat is upstream, not ours, and it should shape how you deploy this.

Beta Frappe Framework app AGPL v3 Real-time collaboration YJS CRDT
01 · What it is

Two products in one app.

Frappe Drive is a self-hosted cloud storage platform with a modern interface, built on the Frappe Framework. The ambition is explicit: storing, sharing and collaborating on files without a per-seat subscription and without your documents sitting in someone else’s datacentre.

It is really two things. Core is the file manager — upload, organise, preview, share, control access. Writer is a collaborative document editor with real-time co-editing, comment threads and versioning. The project’s own account of its history is honest about this: the idea of a Drive-like app had been circulating inside Frappe since 2015, and what began as simple file sharing grew into a collaboration tool as they dug in.

The framework already handles files competently; Drive exists because a standalone, user-facing product was a different problem from a framework capability.

Read the beta label as written

The repository carries an explicit warning: Frappe Drive is in beta, and it is strongly advised to take backups in production use. We are not going to soften that. It does not mean the app is unusable — plenty of software is run in production at this maturity — but it does mean this should not be the only copy of anything you cannot afford to lose, and that your backup restore path should be tested rather than assumed. If that sentence makes a stakeholder uncomfortable, they have understood it correctly.

03 · Writer — the editor

Collaborative documents, CRDT-backed.

Writer is where Drive stops being a file store. It gives you real-time collaborative editing with other users and with guests, annotation threads you can resolve and reply to, manual versioning so you can pin a state worth returning to, automatic versioning as a safety net, and .docx import.

The interesting part is underneath. Real-time collaboration in both the document and the annotation system runs on YJS — a CRDT, or conflict-free replicated data type. Rather than locking a document or reconciling edits on a server, a CRDT lets concurrent edits merge deterministically regardless of the order they arrive in. It is the same family of technique behind most credible collaborative editors, and choosing it rather than inventing a locking scheme is a good sign about the engineering.

04 · Gotchas

Where it gets tricky.

Beta means your backup discipline is the product’s safety margin

The upstream advice is to take backups in production use. Translate that into practice: automated backups, offsite copies, and a restore you have actually performed at least once. Drive holding the only copy of a client deliverable is a risk you chose, not one the project hid from you.

The pooled-versus-quota decision is early and awkward to reverse

You can pool storage across all users or assign per-user quotas. This looks like a settings toggle and behaves like an architecture decision — it shapes how you capacity-plan, what happens when one user fills the disk, and how you bill internal departments if you do. Decide it with the people who will own the storage bill.

Previews and format support are a list, not a guarantee

In-browser preview is a headline feature and its coverage is documented per format. If your workflow depends on previewing a specific file type — CAD, large PDFs, particular video codecs — verify it against the documented list before you promise it to anyone.

AGPL v3 is network copyleft

Drive is AGPLv3. Internal use carries no obligation; offering a modified Drive to third parties over a network does. If you plan to white-label this as a storage product for clients, get the licence read first. Note the inconsistency across the estate — Frappe Wiki is MIT.

It will be compared to Google Drive, and that is the wrong frame

Users arriving from Google Drive or OneDrive will measure this against a product with two decades of engineering and a global CDN behind it. Set the expectation deliberately: you are trading feature depth and edge performance for ownership, residency and the absence of a per-seat bill. That is a reasonable trade for some teams and a bad one for others.

05 · Decision guide

Use it for, skip it for.

Use it when

  • You need file storage and collaborative documents inside infrastructure you control
  • You are already running Frappe and want storage on the same site, with the same users and permissions
  • POPIA or a client contract requires documents to stay in a region and on hardware you can point at
  • Per-seat Google Workspace or Microsoft 365 billing in USD is a cost you want to cut
  • You can commit to real backup discipline — automated, offsite, restore-tested
  • Guest access with controlled permissions is a workflow you need for external collaborators

Skip it when

  • It would become the sole system of record for documents you cannot afford to lose, and backups are aspirational
  • You need the full Google Workspace or Microsoft 365 feature surface — this is not that, and will not be soon
  • Your compliance regime requires a vendor certification that self-hosted software cannot produce
  • Your users are distributed across continents and expect CDN-grade file performance
  • You need a documentation platform with review workflow — that is Frappe Wiki
  • Nobody will own storage capacity planning, and growth is unpredictable
06 · South African context

What this changes for SA delivery.

POPIA — this is the strongest residency card in the Frappe estate

Documents are where personal information actually accumulates: ID copies, payslips, contracts, medical notes, client files. For an SA organisation, self-hosted storage on local infrastructure converts the cross-border transfer question into a non-question. You are not documenting a Section 72 transfer and managing consent — the data never leaves. For regulated SA clients who have been told for years that cloud storage means a US processing agreement, that is a genuinely different conversation.

Bandwidth and egress — the SA-specific cost nobody models

Server-side video streaming and in-browser previews are lovely features and they move bytes. On local hosting with South African bandwidth pricing and a workforce that is partly remote and partly on mobile, egress is a real line item and latency is a real experience problem — especially if your users are not in the same city as the server. Model this before you migrate a media-heavy team. A storage platform that is cheaper per seat and more expensive per gigabyte served is not automatically cheaper.

FX — favourable, with an honest asterisk

Workspace and M365 storage tiers are priced in dollars per user per month and ratchet upward as quotas fill. Self-hosted storage is rand-denominated infrastructure plus your own time. At meaningful headcount the arithmetic favours self-hosting — but count the operational burden properly, and count the beta risk as a cost too. A restore you never tested is not a saving.
