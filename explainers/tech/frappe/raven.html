tech/frappe · Raven · Skill Leaf

Team chat that can
approve the document.

Raven is open-source team chat built as a Frappe app — channels, threads, polls, scheduled messages, native mobile apps. Because it runs on the same site as your ERP, HR and helpdesk, a document link becomes a card, a document event becomes a channel notification, and an approval becomes a permission-checked write from the chat window. Slack's shape, one user table, and no per-seat invoice in dollars.

Live Frappe Framework app AGPL v3 React · Frappe React SDK v3.2.0 · Oct 2026 iOS · Android
01 · What it is

Slack's shape, your database.

Raven is team chat built as a Frappe app. Public and private channels grouped into workspaces, direct messages, threads, mentions, reactions, polls, file sharing with link previews, and search across messages, files, links and people. The feature list is deliberately Slack-shaped, because the point is not a new interaction model — it's the same interaction model with the messages sitting in a tabRaven Message table on a site you control.

The architectural detail that matters: Raven is the React app in a Vue ecosystem. Frappe CRM, Helpdesk and HR all ship Vue 3 frontends on Frappe UI. Raven is built on the Frappe React SDK — React hooks for auth, data fetching and realtime updates. If your team's frontend capability is the reason you picked Frappe, check which way that cuts before you commit to customising the UI.

It also ships native iOS and Android apps that point at any site running Raven 3.1 or later — you enter the site address, sign in, and channels sync with the web app. For a self-hosted chat tool that is the difference between a thing people use and a thing people have an account on.

The part that isn't a Slack clone

Because Raven is a Frappe app rather than an integration, chat sits inside the same permission system as the rest of the site. Pasting a document link renders a card. Document events can post notifications into a channel. You can approve or reject a document from the chat window — not via a webhook round trip to an external service and back, but as a permission-checked write on the same site, by the same user.

That collapses a whole category of plumbing. The common build — "post ERP approvals to Slack and let people action them there" — normally means an app registration, a bot token, a signing secret, an inbound webhook endpoint you now have to host and secure, and an identity mapping between Slack users and ERP users. On Raven that build is configuration, because there is only one user table.

02 · Key doctypes

The data model.

Messages, channels and bots are ordinary documents. Everything below is queryable over the same REST surface the rest of the site uses — which is what makes chat history a reportable asset rather than a vendor's export job.

03 · How it works

REST against the message store.

There is no bot API to learn. Posting a message is creating a document; reading a channel is listing documents with filters. The examples below are the whole integration surface.

# Post a message into a channel as the authenticated user
POST /api/resource/Raven Message
{
  "channel_id": "operations",
  "text": "<p>Stock count variance on WH-CPT-01 exceeds 2%.</p>",
  "message_type": "Text"
}
# Read a channel's recent history
GET /api/resource/Raven Message
  ?filters=[["channel_id","=","operations"]]
  &fields=["name","owner","text","creation","message_type"]
  &order_by=creation desc
  &limit_page_length=50

# Queue a message for Monday 07:00 instead of sending it now
POST /api/resource/Raven Scheduled Message
{
  "channel_id": "operations",
  "text": "<p>Weekly cycle count starts today.</p>",
  "scheduled_time": "2026-11-30 07:00:00"
}

Bots are the interesting half. A Raven Bot is a sender that isn't a person. Point it at a webhook and it relays; set is_ai_bot and give it an instruction, and it becomes an agent in the channel. Raven's AI bots call your own OpenAI-compatible provider — you supply the base URL and key — so the model can be a hosted API or something you run yourself. Nothing is routed through a Frappe-operated inference service.

What a bot may actually do is declared as Raven AI Function records — named tools bound to a doctype and a parameter schema, each carrying a requires_write_permissions flag, and the bot itself gated by allow_bot_to_write_documents. That is the control surface worth knowing: an AI bot in a channel is not given the run of the site, it is given the functions you registered, and write capability is a deliberate second switch rather than a side effect of being useful.

Contrast that with the framework's own MCP endpoint. Frappe v16 serves MCP at /api/v2/mcp with create, update, delete and method-call tools bound only by the calling user's permissions — no per-doctype allowlist. Raven's bot model is narrower by construction. For an agent that sits in a channel where staff will talk to it casually, the narrower surface is the one you want.

04 · Gotchas

Where it gets tricky.

Self-hosted chat means you own uptime

Chat is the tool people notice first when it breaks, and they notice within about ninety seconds. Slack's real product is an SLA and an operations team. If you self-host Raven, that becomes yours — websockets, the realtime layer, push delivery, and the scheduler for reminders and scheduled messages all have to stay up. Budget monitoring before rollout, not after the first outage.

Push notifications need real setup

Web and mobile push are not automatic — they depend on configured notification credentials, and the mobile apps need the site reachable from outside your network over valid TLS. A Raven install that works beautifully on the office LAN and never notifies anyone on the road is the standard first-week failure.

Pilot self-hosting requires Frappe v16

The recommended self-hosted route is Frappe's Pilot installer, which needs Frappe v16 or later. If your bench is still on v15 you can install Raven with bench get-app on the existing bench, but the smooth path assumes you have already done the v16 upgrade.

No federation, no external guests at Slack's level

Raven has guest access with limited, controlled site permissions — useful. It is not Slack Connect. Running shared channels with a client or supplier who is not a user on your site is not the pattern this tool is built for.

Chat history is now a POPIA-relevant records pile

The flip side of "your messages stay in your database" is that your messages stay in your database. Years of staff chat, with files attached, under your responsible-party obligations and your retention policy. This is a benefit only if you actually have a retention policy.

05 · Decision guide

Use it for, skip it for.

Use Raven when

  • You already run Frappe apps and want approvals, document notifications and discussion in one permission model instead of a Slack integration you maintain.
  • Per-seat chat licensing in USD is a line item you want to delete, and you have somewhere to put the hosting.
  • Chat history being queryable — and exportable, and deletable — on your own terms is a compliance requirement rather than a preference.
  • You want AI agents in channels with an explicitly registered tool list, calling a model provider you chose.
  • Your team is one organisation on one site. That is the shape Raven fits best.

Skip Raven when

  • Chat is mission-critical and you have no one to carry a pager for it. Buy the SLA; this is the honest answer more often than this tree's bias would suggest.
  • You need Slack Connect-style shared channels with external organisations, or federation.
  • Your workflow depends on the third-party app ecosystem — the Slack and Teams marketplaces are the actual product for a lot of teams, and Raven has no equivalent.
  • You need voice and video as first-class features. Raven is text, files and threads.
  • You are not otherwise on Frappe. Standing up a Frappe site to run only chat is the wrong reason to adopt a framework.
  • Your organisation is on Microsoft 365 with Teams already paid for inside the licence. Replacing a sunk-cost tool with a self-hosted one you now operate is a cost increase wearing a cost-saving's clothes.
06 · South African context

Where this earns its keep locally.

Two things make self-hosted chat a more serious proposition in South Africa than the global framing suggests: the currency the alternatives bill in, and where the messages sit.

The FX line is the whole argument. Slack and Teams bill per seat in US dollars. A 60-person organisation on a paid Slack tier is carrying a dollar-denominated monthly cost that rises in rand every time the currency moves against you, on a tool whose feature set is not changing. Raven moves that spend to infrastructure and someone's time — both of which you can price in rand and both of which you control. That is an FX hedge as much as a licence decision, and it is the same argument the ERP leaves in this tree make about Odoo Enterprise and SYSPRO.

Be honest about what replaces the licence, though. The saving is real but it is not the full sticker price. You are trading a predictable USD subscription for hosting, backups, monitoring, upgrades and the person who gets called when chat is down during month-end. For an organisation that already runs a Frappe site and already has that person, the marginal cost is genuinely small. For one that doesn't, the licence was buying something.

POPIA and data residency. Staff chat is personal information, and chat attachments are frequently more sensitive than anything in the ERP — ID documents, payslip queries, disciplinary discussion, client records pasted in for convenience. Self-hosting on an SA region (af-south-1, africa-south1, southafricanorth) or local iron keeps it in-country and makes the Section 72 cross-border question disappear rather than needing an answer. It does not make POPIA disappear: you are now the responsible party for a growing archive, which means a retention period, a deletion mechanism and a documented lawful basis. The AI-bot path needs its own line in that assessment — a bot calling an offshore model provider is a cross-border transfer of whatever lands in its context, whatever the site's hosting region.
