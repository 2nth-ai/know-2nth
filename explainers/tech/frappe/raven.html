tech/frappe · Raven · Skill Leaf

Team chat that can
read your doctypes.

Raven is open-source team chat on the Frappe Framework — channels, direct messages, threads, reactions, files, polls. The reason it exists rather than a Slack subscription is the second half: messages can carry a live document from the same site, a doctype event can post into a channel, an approval can be actioned from the conversation, and a bot in the channel can be wired to an LLM — OpenAI, or an Ollama instance on your own hardware.

01 · What it is

Slack's shape, your database.

Raven's chat surface is deliberately unsurprising: workspaces hold channels, channels are Private, Public or Open, you get threads, mentions, custom emoji reactions, file attachments with previews, search, polls, scheduled messages, reminders, web push with quiet hours, and an installable web app on phones. If you have used Slack you do not need a tour.

What makes it a Frappe app rather than a chat app that happens to be self-hosted is that conversations and business records are in the same database. A Raven Message has link_doctype and link_document, so pasting a link to a sales order renders it with its status and key fields. A Raven Channel has linked_doctype and linked_document, so a channel can be the discussion attached to a project or a ticket. Raven Document Notification posts into a channel on New Document, Update, Submit, Cancel or Delete, gated by a condition you write and formatted by a template — no code, no webhook relay, no Zapier. Raven Message Action then lets someone act from the thread, running a Create Document, a Custom Function or a Server Script.

The commercial argument is blunt and holds: there is no per-user price. On a thirty-person implementation where Slack's paid tier is a recurring rand cost indexed to a dollar, chat becomes another app on a bench you are already paying for.

Where the repository actually lives

Raven was built by The Commit Company and development happens at The-Commit-Company/raven; frappe/raven is the Frappe-org home the README and the marketplace listing point at. Both resolve. If you are pinning a branch or filing an issue, check which one the project is treating as canonical at the time — that has moved before.

03 · How it works

Chat as a doctype, agents as a tool list.

Because messages are documents, anything that can call the Frappe REST API can participate in the conversation — including an agent you wrote yourself, with no bot framework in between.

# Post a message into a channel as a bot
POST /api/resource/Raven Message
{
  "channel_id": "operations",
  "text": "Stock for SKU-4410 is below reorder level at three branches.",
  "message_type": "Text",
  "is_bot_message": 1,
  "bot": "inventory-watch"
}
# Attach a live document to the message instead of describing it
POST /api/resource/Raven Message
{
  "channel_id": "approvals",
  "text": "Needs a second signature before Friday.",
  "link_doctype": "Purchase Order",
  "link_document": "PUR-ORD-2026-00231"
}

# Read a channel's recent history
GET /api/resource/Raven Message
  ?filters=[["channel_id","=","approvals"]]
  &fields=["name","owner","text","creation","is_bot_message"]
  &order_by=creation desc&limit_page_length=50
# A notification rule: post when a high-value PO is submitted
POST /api/resource/Raven Document Notification
{
  "notification_name": "Large PO submitted",
  "document_type": "Purchase Order",
  "send_alert_on": "Submit",
  "condition": "doc.grand_total > 250000",
  "enabled": 1
}

The AI bot, in plain terms

A Raven Bot with is_ai_bot set takes an instruction (optionally dynamic_instructions, rendered per message), a model, a reasoning_effort of low, medium or high, and a list of bot_functions. Each function is a Raven AI Function whose type is drawn from a CRUD surface over your doctypes — Get Document, Get List, Get Report Result, Create Document, Update Document, Delete Document, Submit Document, Cancel Document, Set Value, Send Message, Attach File to Document, or a Custom Function you point at a Python path. strict constrains the arguments to the schema; requires_write_permissions marks the function as mutating; allow_bot_to_write_documents on the bot is the master switch.

model_provider is OpenAI or Local LLM. Choosing local means Raven Settings → local_llm_provider (Ollama, LM Studio, LocalAI or any OpenAI Compatible endpoint) and an local_llm_api_url. That combination — chat, business records and the model all inside your own perimeter — is the single most interesting thing in this app for regulated work.

04 · Gotchas

Where it gets tricky.

A write-enabled bot is a privileged actor, not a convenience

The function list includes Delete Document, Submit Document and Cancel Document. Turn on allow_bot_to_write_documents and attach those, and a prompt in a chat channel can submit or cancel a financial document. Anyone who can type in the channel is upstream of that. Grant read functions freely; treat every mutating function as a change to your authorisation model, scope it to one reference_doctype, and keep approvals in Raven Message Action where a person clicks, rather than in a bot that infers.

Chat history is a records-retention problem you now own

Self-hosting removes the vendor and the per-user fee. It also means every message, file and reaction is in your database with no retention policy, no legal hold and no export tooling beyond the Frappe API. Decide at install how long Raven Message rows live and who may read them. Nobody asks this question until the first dispute.

Version compatibility is narrow and Pilot needs v16

The README's compatibility table pairs the develop branch with Frappe version-15 at 15.111 or later, version-16 or develop. Separately, Pilot — now the recommended self-hosting route — requires Frappe v16 or later. On an older v15 bench you can run Raven but not Pilot, so plan the upgrade rather than discovering the gap mid-install.

Push notifications need a service behind them

push_notification_service is Frappe Cloud or Raven, with a server URL, API key and secret, plus a VAPID key for web push. Self-host without configuring one and the app works while the tab is open and silently fails to notify anyone who closed it — which users experience as "the chat is broken".

No voice or video of its own

There is a hook for Frappe Meet URLs in settings, and Zoom-style calling is not part of Raven. If a client's current behaviour is huddles and screen shares, Raven does not replace that half of Slack and saying so early avoids an awkward demo.

05 · Decision guide

Use it for, skip it for.

Use Raven when

  • Your team already works inside a Frappe or ERPNext site all day, and the conversation about a document should sit next to the document.
  • You want doctype events in a channel without a webhook relay or a third-party automation subscription.
  • Per-user SaaS chat pricing in dollars is a line item worth removing.
  • You want an LLM assistant over your own business records, and you want the option of running the model locally.
  • Internal chat must stay inside your own infrastructure for policy reasons.

Skip Raven when

  • You need voice, video or screen sharing in the same tool. It doesn't do them.
  • You need the integration ecosystem — the connector for every SaaS tool your team already uses. Raven integrates deeply with Frappe and shallowly with everything else.
  • You need enterprise compliance features: eDiscovery, legal hold, DLP, retention policy enforcement, guest access across organisations.
  • Most of the people who need to be in the chat are not Frappe users. Identity lives on the site; outsiders are awkward.
  • Nobody will own it. Self-hosted chat going down is a different class of incident from a reporting app going down — it is the channel people would use to report the outage.
06 · South African context

Where it lands in SA delivery work.

The strongest residency story in the Frappe stack

Most "AI in your business system" proposals in South Africa stall on the same question: where does the prompt go? Raven is the rare case with a clean answer. Chat on a bench in a Johannesburg or Cape Town data centre, business records in the same database, and model_provider set to Local LLM pointed at an Ollama or vLLM endpoint on your own hardware — nothing crosses a border, so there is no Section 72 transfer to document and no US-hosted vendor in the chain. The trade is model quality: a model you can serve locally is not Opus or Fable. For triage, extraction, summarising a thread or filling a form, that gap often doesn't matter; for judgement, it does. Pick per task, and read where LLM inference runs in SA before promising residency with a hosted model.

POPIA · the OpenAI switch changes your compliance posture

Flip enable_openai_services and the bot's context — which, with read functions attached, means customer and employee records from your doctypes — leaves the country. That is a cross-border transfer of personal information and needs the same treatment as any other: a lawful basis, a record of the flow, and a client who knows. The same applies to the Google document parser option. None of this makes the feature wrong; it makes it a decision that belongs to the client's information officer rather than to whoever had admin rights that afternoon.

Where it fits an SA implementation

The pattern that works: don't try to replace WhatsApp, which is where South African operational teams actually live. Use Raven for the conversations that need to be attached to records and auditable — approvals, exceptions, handovers between shifts, the thread on a disputed invoice — and let the informal traffic stay where it is. A channel bound to a document with Raven Message Action for the approval is a genuine improvement on an approval that happened in a WhatsApp group and left no trace on the document.
