tech/frappe · Raven · Skill Leaf

Team chat that can
read your ERP.

Raven is an open-source messaging platform built on the Frappe Framework — channels, direct messages, threads, reactions, file sharing, and a React Native mobile app. The chat is the ordinary part. What makes it worth a leaf is that Raven runs inside the same site as ERPNext and Frappe HR, so a message can carry a live document preview, fire on a document event, run a workflow action, or hand work to an agent — without a webhook, a bot token, or a second system of record.

Live Frappe Framework app AGPL v3 React + React Native
01 · What it is

Slack's shape, your database.

Raven does what Slack, Teams, and Mattermost do — channels organised by topic or project, direct messages, rich-text composition with mentions and code blocks, drag-and-drop file sharing, reactions with custom emoji, inline replies and threads. If you have used any team chat tool in the last decade, there is nothing to learn.

The difference is where it sits. Raven is a Frappe app, so it installs onto an existing bench alongside ERPNext, Frappe HR, or Frappe CRM. Users are the same users. Permissions are the same permissions. And because every business record on that site is already a doctype with a REST surface, Raven can share an ERPNext document into a channel with a customisable preview, raise a notification when a document event fires, run a workflow action from the chat, and print a document without leaving the conversation.

That is the whole argument. Chat next to your ERP is a tab you alt-tab to. Chat inside your ERP is a place where the conversation and the record are the same object graph.

Provenance worth knowing

Raven was built by The Commit Company and now lives in the frappe GitHub organisation. The lineage still shows: the production Docker image is published as ghcr.io/the-commit-company/raven, and the community forum runs at community.ravenapp.cloud rather than on the main Frappe discuss instance. Nothing sinister — it is simply a community-origin app that got adopted, and it is worth knowing which door to knock on when you need support.

02 · Under the hood

Two frontends, one Frappe backend.

Raven is a Frappe backend with two separately-built clients. This matters more than it sounds — it is the single biggest driver of how much work self-hosting actually is.

LayerWhat it's built onWhat that means for you
BackendFrappe Framework — Python, MariaDB or Postgres, Redis, socket.ioSame bench, same doctypes, same REST API and hooks as every other Frappe app. Realtime is Frappe's existing socket layer, not a new service.
Web clientReact, built with Vite; Radix UI for components, TipTap for the composer, emoji-mart for the pickerA single-page app served from the site, not a Frappe Desk page. Styling is Tailwind. Data access goes through frappe-react-sdk.
Mobile clientReact Native on Expo, NativeWind, Reanimated, Gesture Handler, ZeegoA real native app — and a real release pipeline. See the gotchas.
Push & telemetryFirebase — push notifications, crash analytics, performance monitoringA third-party data path out of your otherwise self-hosted stack. Worth naming explicitly in a POPIA assessment.

Authentication is the grown-up part

Raven inherits Frappe's auth stack and exposes it properly: all the popular OAuth providers plus custom OAuth, login via email link, two-factor over email, SMS or an authenticator app, and LDAP. For an organisation that already runs directory-backed identity, this is the difference between "we could try it" and "it passes the security review".

03 · Raven AI

Agents built where the records already are.

Raven ships an agent layer: automate tasks, extract data from files and images, and execute multi-step processes by messaging an agent. Agents are configurable from the UI without writing code.

Read that carefully, because the interesting claim is not "AI in chat" — every chat tool has that now. The interesting claim is that the agent is already inside the permissions boundary of your system of record. An agent that can read a Sales Order does not need an integration, an API key, or a synced copy of your data. It needs a role.

That is also the risk. "No code" means the blast radius of an agent is decided by whoever configured its role and its tools, not by a developer reading a diff. Before you let one loose on a production site, be specific about three things: which doctypes it can read, which it can write, and which channels it is reachable from. Frappe's role and permission model is expressive enough to answer all three — but it will not answer them for you, and the default of "it works" is rarely the default of "it is scoped".

The honest positioning against a general agent framework

If your agent's job is "look at this invoice attachment and raise a Purchase Invoice", Raven AI is the short path — the data, the permissions, and the human who approves it are all in one place. If your agent's job spans systems your ERP does not own, you want a real orchestration layer (LangGraph, the Agent SDK) talking to Frappe over REST or MCP, with Raven as the human-in-the-loop surface rather than the runtime. Choosing Raven AI for the second job is how you end up rebuilding an orchestrator inside a chat app.

04 · Gotchas

Where it gets tricky.

The mobile app needs an Expo development build, not Expo Go

Raven's mobile client will not run in Expo Go. Developing against it requires Xcode and/or Android Studio locally plus the EAS CLI, and shipping a branded build to your own staff means your own Apple Developer and Play Console accounts, your own signing keys, and your own review cycles. Budget this as a small mobile project, not a checkbox. A team that only needs the web client can ignore all of it.

Firebase is in the path for push

Push notifications, crash analytics, and performance monitoring go through Firebase. On a self-hosted deployment chosen specifically for data residency, that is an external dependency that carries message metadata off your infrastructure. Either accept and document it, or run web-only and lose push.

AGPLv3, and the client code is part of it

Raven is AGPL v3. If you modify it and offer it over a network to third parties, the licence obliges you to offer the corresponding source. Internal use by your own organisation is fine. Embedding a customised Raven in a product you sell to clients is a licensing conversation, not an engineering one — and note that other apps in the same ecosystem are licensed differently: Frappe Builder and Frappe Wiki are MIT. Do not assume the licence by association.

Chat becomes a records surface the moment you install it

The instant staff start discussing customers, employees, or salaries in Raven, those messages are records — discoverable, subject to retention policy, and in scope for POPIA. Frappe gives you the storage and the permissions; it does not give you a retention policy. Write one before rollout, not after the first subject access request.

Sizing is on you

A chat app is a persistent-connection, high-write workload bolted onto a bench that was sized for ERP traffic. Socket.io connections, message volume, and file uploads all land on the same server as your month-end close. Put Raven on its own bench, or size the shared one deliberately.

05 · Decision guide

Use it for, skip it for.

Use Raven when

  • You already run ERPNext, Frappe HR, or Frappe CRM and want conversations attached to the records they are about.
  • Per-seat chat licensing in USD is a real line item and your headcount is growing.
  • Data residency rules out a US-hosted SaaS chat tool for internal discussion of customer or employee data.
  • You want an agent that can act on business documents inside an existing permissions boundary, with a human approving in the same thread.
  • Your identity stack is LDAP or OAuth-backed and you need chat to honour it.

Skip Raven when

  • You are not on Frappe. Running a whole bench to get a chat app is the wrong trade — take Mattermost or Zulip instead.
  • You need the integration marketplace. Slack has thousands of connectors; Raven has the Frappe ecosystem and whatever you write.
  • You need voice or video calling, huddles, or screen sharing. Raven is text, files, and threads.
  • You need external collaboration with clients and suppliers at scale — Slack Connect and Teams federation have no equivalent here.
  • You cannot accept Firebase in the push path and your users will not tolerate web-only.
  • Your organisation needs eDiscovery, legal hold, and DLP tooling out of the box. You would be building all three.
06 · South African context

Where Raven earns its place in SA delivery.

POPIA · chat is personal information

Internal chat about customers, candidates, patients, or employees is processing of personal information under POPIA, whatever the tool. Self-hosting Raven on an SA region (af-south-1, africa-south1, southafricanorth) keeps the message store and the attachments in-country, which removes the Section 72 cross-border question for the bulk of it. Two caveats that a residency claim has to survive: Firebase push metadata leaves the country, and any agent that calls a hosted model sends whatever you put in the prompt to that model's region. Name both in the assessment rather than discovering them in an audit.

FX · the arithmetic that actually decides this

Per-seat chat is USD-billed and re-prices against the rand every year without you doing anything. Raven's cost is your infrastructure plus your time, billed in rand. For a fifteen-person studio the saving is real but small, and the self-hosting effort probably eats it. At a hundred-plus seats the arithmetic flips hard, and it keeps flipping further every time the rand moves. Run the number at your headcount and your own hourly rate before treating "open source" as "cheaper".

Bandwidth and the mobile reality

A meaningful share of SA staff are on mobile data, not fibre, for part of the week. A chat app that streams attachment previews and keeps a socket open is a data-cost decision for those users. Raven's mobile client is a real native app rather than a wrapped web view, which helps — but test it on a throttled connection before you roll it out to a field team, and check what your file-sharing culture does to a 2GB monthly bundle.
