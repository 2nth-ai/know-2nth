tech/frappe · Learning · Skill Leaf

Courses, cohorts
and a certificate at the end.

Frappe Learning — the app still installed as lms — is an open-source learning management system on the Frappe Framework. Courses break into chapters and lessons, learners are grouped into batches with live classes, quizzes and assignments carry the assessment, and completion issues a certificate. It began in 2021 as the platform for FOSS United's Mon.School and became a product because the alternatives were worse.

Live Frappe Framework app AGPL v3 Requires frappe/payments
01 · What it is

An LMS that didn't want to be Moodle.

Frappe Learning does the standard LMS job: publish structured course content, enrol learners, assess them, certify them. What it is reacting against is stated plainly in its own README — the team evaluated Moodle for Mon.School, found the forms long and the interface confusing, and wrote their own. The result is narrower than Moodle and much easier to get a first course into.

The content model is three levels: an LMS Course holds Course Chapter records, each holding Course Lesson records. Lessons are Markdown with embedded video, files and inline assessments. On top of that sits the cohort layer: an LMS Batch groups learners with a start and end date, a timetable, seat count and optional Zoom or Google Meet live classes. A course can be taken self-paced or run as a batch, and disable_self_learning on the course is the switch that forces the cohort route.

Assessment is more serious than the quick tour suggests. LMS Quiz carries max_attempts, passing_percentage, shuffle_questions, a duration, optional negative marking, scheduling windows, and proctoring with a violation threshold — there is an LMS Quiz Violation Log doctype behind that. LMS Assignment takes submissions as documents or PDFs for manual grading, and LMS Programming Exercise runs submitted code against test cases. Certificates are LMS Certificate documents with an issue date, an optional expiry and a template you can replace.

It is also a Frappe app, which is the actual reason to pick it

Every object above is a doctype on your site, which means learner records sit next to the rest of the business. If the same site runs Frappe HR, a LMS Certificate is queryable against an Employee without an integration — which is how you answer "who on this crew holds a current induction?" as a report instead of a spreadsheet. That is the pitch. An LMS that only did courses well would not be worth the framework.

03 · How it works

REST against enrolments and progress.

The reporting questions a client actually asks — who is behind, whose certificate expires this quarter — are ordinary Frappe queries.

# Learners on a course who have started but not finished
GET /api/resource/LMS Enrollment
  ?filters=[["course","=","popia-for-operations"],["progress","<",100],["progress",">",0]]
  &fields=["member","member_name","progress","current_lesson"]
  &order_by=progress asc
# Certificates expiring in the next 90 days — the compliance question
GET /api/resource/LMS Certificate
  ?filters=[["expiry_date","between",["2026-10-19","2027-01-17"]]]
  &fields=["member_name","course_title","issue_date","expiry_date"]
  &order_by=expiry_date asc

# Enrol a learner into a batch
POST /api/resource/LMS Batch Enrollment
{
  "batch": "induction-2026-q4",
  "member": "learner@example.co.za"
}
# Quiz results for a cohort, to see whether the assessment discriminates
GET /api/resource/LMS Quiz Submission
  ?fields=["member","quiz","score","percentage","creation"]
  &filters=[["quiz","=","induction-assessment"]]
  &limit_page_length=0

Field names are not guaranteed across versions

The doctype names above are read from the current develop branch. Frappe Learning moves, and submission doctypes in particular have been reshaped before. Before you build a report or an agent against a field, confirm it on the version you installed — GET /api/method/frappe.client.get_list with doctype=DocField, or just open the doctype in Desk. This applies to the whole Frappe ecosystem, but it bites hardest in the newer apps.

04 · Gotchas

Where it gets tricky.

Code exercises default to a Frappe-hosted runner

Programming exercises execute submitted code through a service at livecode_url in LMS Settings. Leave that blank and the app falls back to a hard-coded default, https://falcon.frappe.io — meaning learner-submitted code leaves your server for a third party you have no contract with. If you use programming exercises at all, set livecode_url to a runner you control, and if you can't, disable the feature rather than shipping it quietly.

The payments app is a hard dependency

required_apps in hooks.py is ["frappe/payments"], so you install payments whether or not you ever sell a course. That matters for the install order on a self-managed bench: bench get-app payments before bench get-app lms, or the install fails.

The money model is shaped for India

LMS Payment carries gstin, pan and amount_with_gst; LMS Settings has apply_gst and an exception_country list. That is Indian GST, not South African VAT, and there is no SA tax-invoice logic in the app. If you are selling courses to SA customers, treat paid enrolment as a payment record and raise the tax invoice in ERPNext or your accounting system — don't try to make this doctype the invoice.

Gateway coverage comes from frappe/payments, and it is thin for SA

The gateways that app ships are Stripe, PayPal, Braintree, Razorpay, Paytm, GoCardless, Paymob and M-Pesa. For a South African seller that realistically means Stripe or PayPal; PayFast, Peach, Ozow and Yoco are not there. Confirm the gateway before you promise paid courses, not after.

Proctoring is a browser-side honour system

enable_proctoring and max_violations log suspicious events during a quiz. That is a deterrent and an audit trail, not invigilation. Don't let a client hang a certification whose integrity actually matters — a ticketed trade qualification, say — on it. Use an evaluator and LMS Certificate Evaluation for those.

SCORM support is at the chapter level

Course Chapter can be a SCORM package rather than a set of lessons, which is how you bring existing commercial courseware in. Expect the usual SCORM experience: packages that work, packages that half-work, and tracking that reports completion but not much else. Test the specific package before you quote the work.

05 · Decision guide

Use it for, skip it for.

Use Frappe Learning when

  • You need internal training with records that tie to employees — induction, safety, compliance refreshers — and you already run Frappe or ERPNext.
  • Certificate expiry is the reporting question that matters, and you want it as a query rather than a spreadsheet.
  • You run cohorts: fixed-date batches with a timetable and live sessions, not just a content library.
  • You want to publish a small paid course catalogue and Stripe or PayPal is an acceptable gateway.
  • You would otherwise pay per-seat for a hosted LMS whose features you use a fraction of.

Skip Frappe Learning when

  • The qualification is externally accredited and the integrity of assessment has to hold up to scrutiny. Browser-side proctoring won't.
  • You need SA VAT invoicing on course sales out of the box. The tax model is Indian GST and retrofitting it is not a small job.
  • Your learners are consumers at scale and the storefront is the product — a hosted platform will out-market this on checkout, coupons and course discovery.
  • You need deep learning analytics: cohort comparisons, item analysis on questions, predictive drop-off. The reporting is basic.
  • You aren't running Frappe. The framework is the price of entry, and for a standalone LMS that price is too high.
  • Programming exercises are central and you cannot host your own code runner.
06 · South African context

Where it lands in SA delivery work.

The compliance-training use case is the strong one

South African employers carry a lot of mandatory training — occupational health and safety induction, POPIA awareness, site-specific competency — and the usual evidence is an attendance register in a lever-arch file. LMS Certificate with an expiry_date, joined to Employee in Frappe HR on the same site, turns "prove everyone on site is current" into a report. That, not course authoring, is normally what justifies the install.

POPIA · learner records are personal information, and quiz logs are more than that

Enrolments, progress, quiz scores and submitted assignments are personal information about employees, and assessment results are the kind of record that affects someone's employment. Three things to settle at design time: who may read LMS Quiz Submission (the default Frappe roles are more generous than most HR policies), how long submissions are retained once a certificate is issued, and whether proctoring violation logs are kept at all — a log of flagged behaviour during an assessment is exactly the sort of data a learner is entitled to ask about. If you leave the default code runner in place, submitted code also crosses a border; see the gotcha above.

FX · dollar-priced courses, rand-priced delivery

LMS Course carries both course_price in a chosen currency and a separate amount_usd, and LMS Settings has show_usd_equivalent. Useful if you sell across borders, and a trap if you forget it: a USD figure captured once does not track the rand, so a stale amount_usd quietly misprices your catalogue. Pick one currency as authoritative and treat the other as display. Hosting cost itself is rand-denominated if you self-host; Frappe Cloud is not, and has no SA region.
