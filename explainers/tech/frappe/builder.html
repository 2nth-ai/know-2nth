tech/frappe · Builder · Skill Leaf

A page builder wired
to your doctypes.

Frappe Builder is a visual website builder that runs as an app on your Frappe site. Drag blocks onto a canvas, bind them to records with a Python data script, give a page a dynamic route, and publish plain HTML and CSS with no JavaScript unless you ask for it. MIT licensed — the one app in the suite that isn't AGPL — and its AI assistant talks to a model endpoint you nominate.

Live Frappe Framework app MIT licence Vue · Frappe UI v1.40.0 · Nov 2026 Static HTML output
01 · What it is

A page builder that can read your database.

Frappe Builder is a visual website builder: you drag blocks onto a canvas, set properties in a panel, and publish. Webflow and Framer do that too. The difference is where it sits — Builder runs as an app on your Frappe site, so a page can query the doctypes already there. A page_data_script is Python that fetches records; a block repeats per record; a dynamic_route like /blog/:slug gives each record its own URL. The marketing site and the customer portal stop being a separate system that has to be fed by an API someone maintains.

The output is worth noting because it is unusual for this category: published pages are plain HTML and CSS, with no JavaScript unless you add it. No framework runtime shipped to the browser, no hydration. For a brochure site, a landing page or a docs-adjacent portal, that is the right answer and it is the answer most visual builders cannot give.

Unlike the rest of the Frappe suite, Builder is MIT licensed rather than AGPL. If you are building client sites and the copyleft question has been the blocker on adopting Frappe tooling commercially, this one is a different conversation.

Design tokens, light and dark, as records

Builder Token holds a value and a dark_value, with a type and a group. Colours and fonts are therefore not strings scattered across pages — they are records, and dark mode is a second value on the same token rather than a parallel stylesheet. That is the same discipline the design domain in this tree argues for, enforced by the data model instead of by code review.

Components behave the same way: Builder Component stores a block tree with props, and editing the component propagates to every page using it. Combined with tokens, this is a usable design system for a small team — not a full one, but the parts that actually get neglected.

03 · How it works

Python on the page, doctypes underneath.

Two mechanisms carry most of what makes Builder more than a canvas: the data script that runs server-side before render, and the dynamic route that turns one page into many.

The data script. Each page can carry a page_data_script — Python evaluated server-side, returning data the blocks bind to. This is ordinary Frappe code, so it respects the same permission model as everything else on the site.

# Page data script — published case studies for a repeater block
projects = frappe.get_all(
    "Project",
    filters={"published": 1, "sector": "Construction"},
    fields=["name", "project_name", "summary", "hero_image", "route"],
    order_by="completion_date desc",
    limit_page_length=12,
)

The dynamic route. Set dynamic_route on a page and give it a route like /case-study/:name. One page definition then serves every matching record, each at its own URL, each rendered server-side as static HTML. That is the whole mechanism behind a blog, a case-study library, a product catalogue or a job board on a Frappe site — without a headless CMS, a build step or a deploy hook.

Bob, and where your prompts go. Builder ships an AI assistant that generates and edits pages from a description, using the site's existing tokens and components; it asks before creating form storage and its changes can be reverted. The part worth knowing is the plumbing: Builder AI Provider carries a litellm_provider, an api_base, an api_key and a from_site_config flag — so the model endpoint is yours to choose, and the key can live in site config rather than the database. You decide which jurisdiction the prompts land in. That is a materially better posture than a builder that routes everything through its vendor's account, and it is the difference between an AI feature you can put in a POPIA assessment and one you cannot.

04 · Gotchas

Where it gets tricky.

Pilot is pre-release and wants v16

The recommended self-hosting installer is Frappe Pilot, which is still pre-release and requires Frappe v16 or later. The ordinary bench route works, but the "follow the quick start" path assumes you have already upgraded. Production servers must be Linux; macOS is a development environment only.

Data scripts are server-side Python on a web page

Powerful, and exactly as dangerous as that sounds. A data script is code, and whoever can edit a page can write it. Treat page edit rights on a Builder site as something close to developer access, and keep the role list short — this is not the same risk profile as letting someone edit copy in a CMS.

The Figma plugin is beta

There is a Figma plugin, and it is labelled beta. Plan handover as a rebuild in Builder informed by the design, not as an import. Treating a beta import path as a production workflow is how a site launch slips.

First-party analytics still collects personal information

Builder Page Click gives you page views, unique visitors and referrers with no third-party tag — genuinely good for privacy and for Core Web Vitals. But you are now the one storing visitor_id records. That needs a cookie or tracking notice and a retention period like any other collection; "we don't use Google Analytics" is not by itself a POPIA answer.

It is not a web application framework

Builder makes pages. Anything with real interaction — multi-step state, a logged-in dashboard, complex forms — belongs in a Frappe app with a proper frontend, or in the Frappe Desk. Pushing Builder into application territory via client scripts gets unpleasant quickly.

05 · Decision guide

Use it for, skip it for.

Use Frappe Builder when

  • You already run a Frappe site and the website needs to show what is in it — case studies, listings, a catalogue, a job board — without a separate CMS and a sync job.
  • You want published output to be plain HTML and CSS, for speed, for crawlers, or because the audience is on poor connectivity.
  • MIT licensing matters because you are building sites for clients and AGPL was the blocker.
  • A small team needs design tokens and shared components enforced by the tool rather than by discipline.
  • You want an AI page assistant whose model endpoint and API key you control.

Skip Frappe Builder when

  • You are not on Frappe. Standing up a Frappe site to host a brochure page is disproportionate — use a static site generator.
  • The site is the product and needs a mature ecosystem: CMS plugins, e-commerce, membership, SEO tooling, a marketplace of templates. WordPress and Webflow win this on ecosystem, not on architecture.
  • You need a large content team working in parallel with editorial workflow, scheduled publishing and granular approvals. Page edit rights here are close to developer rights.
  • Your designers will hand over Figma files and expect fidelity on import. The plugin is beta.
  • You need real application behaviour rather than pages. That is a Frappe app, not a page builder.
06 · South African context

Plain HTML is a performance budget, and ZAR is the pricing story.

Two local realities make Builder's output model and licence more interesting here than the feature comparison suggests.

Shipping no JavaScript is a connectivity decision. A meaningful share of South African traffic arrives on mobile data, on mid-range Android handsets, on networks where latency is the constraint rather than bandwidth. A page that is plain HTML and CSS with WebP images — auto_convert_images_to_webp is a setting, not a build plugin — renders on first paint instead of after a framework bundle downloads and hydrates. For a landing page measured on conversion, or a portal used by people in the field, that is the difference between a page that works and a page that works on the office fibre. Test on a throttled connection, not on your laptop.

The licence and currency arithmetic. Webflow, Framer and the hosted builders bill per seat and per site in US dollars, so an agency's tooling cost rises in rand on every FX move while the feature set stays still. Builder is MIT, self-hosted, and the cost is infrastructure and skill — both priceable in rand. For a small SA studio running client sites that is a genuine structural advantage, and the MIT licence means it can be used in commercial client work without the AGPL conversation the rest of the Frappe suite requires.

Be honest about the trade, though. You are taking on hosting, TLS, backups and upgrades for every client site, and Pilot — the tool meant to make that pleasant — is pre-release. For an agency with no platform engineer, a hosted builder's dollar invoice is buying real operational cover, and saying so to a client is better than discovering it during an outage. The POPIA position is the clearer win: self-hosted in an SA region, first-party analytics with no third-party tag, and an AI provider endpoint you nominate means the data-flow section of an impact assessment is short and truthful.
