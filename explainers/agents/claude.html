agents · Claude · Skill Leaf

Reasoning quality, priced and tiered.

Claude is Anthropic's flagship model family. Four current tiers: Fable 5.1 — a Mythos-class model, the top tier above Opus — for demanding reasoning and long-horizon agentic work, Opus 5.5 for long-running agentic coding and knowledge work, Sonnet 5.5 for the best speed/intelligence trade, Haiku 5.5 for high-volume routing and classification. All four ship 1M context and 128K max output. Adaptive thinking, MCP-first tool layer, vision and computer use built in. The default for production agents that need long-context reasoning, reliable function-calling, and instruction-following beyond what current open-weights models reach.

01 · What it is

Anthropic's flagship family.

Claude is the model family from Anthropic, the AI safety company founded in 2021 by former OpenAI researchers. The first Claude model shipped in early 2023; the family has been on a steady release cadence since, and the 5.x generation is current as of October 2026. Anthropic's own guidance is to start with Opus 5.5 for most workloads and reach for Fable 5.1 only when your evals on Opus 5.5 at higher effort still fall short.

Where GPT and Gemini compete on raw capability and ecosystem reach, Claude has historically led on three things: instruction-following reliability (does what you ask, even when you ask weird things), long-context reasoning quality (uses 200k+ context windows well, doesn't degrade like cheaper models), and safety-focused behaviour (refuses cleanly, hallucinates less in adversarial domains, avoids the "confidently wrong" failure mode that plagues mid-tier models). Those three properties make it the default choice for production agents that have to be right and have to be auditable.

Distribution: Claude is available via the Anthropic API directly, via AWS Bedrock (callable from af-south-1 Cape Town, though inference routes globally — see where LLM inference runs in SA), via Google Cloud Vertex AI, via the Claude.ai web app, the Claude Desktop app, the Claude Code CLI, and through every major aggregator (OpenRouter, LangSmith, etc.). Enterprise plans include Claude Enterprise with SSO, audit logging, and admin controls.

The family naming convention

Most Claude versions follow Claude {Tier} {Major.Minor}. Tier is the size class (Opus / Sonnet / Haiku — large / medium / small). Major is the model generation; minor is the within-generation iteration. So Claude Opus 5.5 is the second Opus 5.x release. The API model ID drops the "Claude" prefix and uses dashes: claude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5. Fable 5.1 sits outside the size ladder: it's a Mythos-class model — a distinct top tier above Opus — with ID claude-fable-5-1. One versioning detail that bites in production: from the 4.6 generation on, those dateless IDs are pinned snapshots in their own right, not floating aliases, so claude-opus-5-5 will not silently become 5.6 under you. There is also a Mythos 5.1 at the same price and capability, restricted to organisations cleared through Anthropic's verification programmes.

02 · The Claude lineup

Four tiers, one quality curve.

The Claude family is deliberately tiered. Each tier is meaningfully cheaper than the one above and meaningfully less capable on the hardest tasks. The right production pattern is multi-tier routing: Haiku for the volume work, Sonnet for the default, Opus for hard cases, Fable 5.1 for the genuinely hardest and longest-horizon ones. The Anthropic Agent SDK supports this routing trivially — sub-agents can run on different tiers. Note what changed in the 5.x generation: context is no longer a tier differentiator. All four current models ship 1M context and 128K max output, so the choice is purely about reasoning depth, latency and price.

Tier · Mythos-class

Claude Fable 5.1

The top tier, above Opus. Built for demanding reasoning and long-horizon agentic work, with its lead widening as tasks get longer and more complex — deep software engineering, scientific research, and vision. The most capable and most expensive Claude model, and the slowest. 1M context, 128K max output, high default effort. Reach for it when correctness on a hard, multi-step task outweighs cost — or when Opus 5.5 at higher effort still misses your eval bar.

Tier · frontier

Claude Opus 5.5

The current Opus, and Anthropic's recommended starting point for most workloads. Built for long-running agentic coding and knowledge work: deep research, complex code review, multi-step planning. 1M context, 128K max output. Note the default effort is medium, one step below the rest of the lineup — set it explicitly if you want more. At $4 / $20 it is also cheaper than the Opus 4.x and Opus 5 it replaced.

Tier · default

Claude Sonnet 5.5

The best combination of speed and intelligence — a strong fraction of Opus quality at half the price and noticeably lower latency. 1M context, 128K max output, high default effort. The right pick for high-throughput agent work where Opus 5.5 is more model than the task needs.

Tier · volume

Claude Haiku 5.5

The fastest, cheapest tier. Best for classification, routing, summarisation and structured extraction at high throughput. Lower reasoning depth, but it now ships the same 1M context as the tiers above it — a real change from Haiku 4.5's 200K. Good fit for "first-pass" agents that escalate when needed. Watch the price tier: prompts over 100K tokens bill at 5× the headline rate.

Capability · cross-tier

All tiers ship

Tool use / function calling, vision (image input), MCP-native integration, structured outputs (JSON-schema-constrained), adaptive thinking, computer use (vision + UI control), prompt caching, streaming. 1M context and 128K max output across all four tiers, with a June 2026 reliable-knowledge cutoff.

Adaptive thinking — the Claude differentiator

Every current Claude model supports adaptive thinking: the model decides on its own when and how much to "think before answering," producing internal reasoning that lifts answer quality on hard tasks. On Fable 5.1 and Opus 5.5 it is always on — you cannot turn it off, only turn it down. You steer depth with the effort parameter (low through max) rather than a fixed token budget. The older fixed budget_tokens knob is deprecated on Opus 4.6 / Sonnet 4.6 and rejected outright on everything newer, so code carrying it forward from a 4.x integration will 400. The practical consequence for cost control: effort is the lever, not a token ceiling — and the defaults differ by model (medium on Opus 5.5 and Haiku 5.5, high on Fable 5.1 and Sonnet 5.5), which is easy to miss when you switch tiers and your bill moves.

03 · vs GPT, Gemini, Llama

Where Claude is the right pick — and where it isn't.

Honest cross-family positioning. Each model family has a real strength and a real constraint. Most production stacks in 2026 use multiple families for different work; few teams pick one and use it for everything.

FamilyStrengthsWatch out for
Claude (Anthropic)Best instruction-following, strong long-context reasoning, native extended thinking, tight MCP integrationClosed model; USD billing; rate limits hit hard at high volume on free tier
GPT (OpenAI)Largest API ecosystem, broadest tooling, strong structured outputs, leading on multimodal extremesVoice / video / DALL-E billed separately; more "confidently wrong" failure mode than Claude
Gemini (Google)Largest context window (1M+ on Pro/Ultra), native search grounding, voice via Live API, GCP integrationLess consistent on instruction-following than Claude; Gemini-only via ADK/Vertex unless via OpenRouter
Llama (Meta, open-weights)Open weights, runs locally via Ollama, largest community fine-tune ecosystemSmaller frontier gap; instruction-following lags Claude/GPT; Meta licence has commercial restrictions over 700M MAU
Gemma (Google, open-weights)Open weights, multimodal, frontier-lab safety tuning, runs locallySmaller community fine-tune ecosystem than Llama; not as code-strong as Qwen-coder

The hybrid that's actually shipping in 2026

Most production agent teams use two or three model families together. Common patterns: Claude for the orchestrator + reasoning steps, GPT for tool-calling-heavy sub-agents, local Ollama-Gemma for PII-bearing pre-processing, Gemini for very-long-context tasks (1M+). The Agents domain hub frames this explicitly: "the question isn't which framework or which model, it's which framework where and which model when." Multi-model is the production reality.

04 · Pricing reality

Frontier-tier pricing, with real production trade-offs.

Claude is not cheap at the top tier. Sonnet 5.5 is half the price of Opus 5.5 and close in quality — for most high-throughput production work, Sonnet is the right default. Haiku 5.5 is cheap enough for genuine volume; Fable 5.1 is the premium you pay only when a hard, long-horizon task has to be right. Pricing is USD per million tokens, with separate input and output rates, and thinking tokens billed at the output rate. Always check claude.com/pricing for current numbers — the rates below were verified against Anthropic's pricing documentation in October 2026, but Anthropic adjusts pricing as generations evolve.

List rates, per million tokens (input / output):

  • Fable 5.1 — $10 / $50. The top tier; 2.5× Opus 5.5 on both input and output. Worth it when a hard, multi-step task's correctness outweighs cost — not for volume.
  • Opus 5.5 — $4 / $20. Frontier-class, and a 20% cut on the $5 / $25 that Opus 5 and the whole Opus 4.x line carried. The hard-reasoning default before you reach for Fable.
  • Sonnet 5.5 — $2 / $10. Half of Opus 5.5 — the right default for production volume.
  • Haiku 5.5 — $0.10 / $0.50 for prompts up to 100,000 tokens, $0.50 / $2.50 above that. Cheapest by a wide margin, but the cliff is real: a RAG agent that routinely stuffs 150K tokens of context into Haiku is paying the higher tier on every call.
  • Prompt caching — cache reads cost 10% of base input on most models, 5% on Opus 5.5 and Sonnet 5.5, and 2.5% on Fable 5.1. Writes are 1.25× base input for the 5-minute cache and 2× for the 1-hour cache. The single biggest saver for agents that re-send the same system prompt and document set.
  • Batch API — 50% discount on input + output for non-urgent workloads. Useful for nightly processing.

Output is billed 5× input across all four tiers. The 1M context window is at standard rates on every current model — no long-context premium. The Haiku 100K threshold above is the one exception.

The per-token price cut is not the whole story

Claude 4.7 and later use a newer tokeniser than Sonnet 4.6 and earlier, and Anthropic documents it as producing roughly 30% more tokens for the same text (the exact figure depends on content and workload shape). So a headline input price that dropped from $5 to $4 does not automatically mean a 20% smaller bill if you came off a pre-4.7 model — the same document now counts as more tokens. The practical move when you migrate: re-baseline with the token-counting endpoint against your real prompts rather than scaling your old token counts by the new price. The same arithmetic applies to the context window: 1M tokens is about 555,000 words on the current tokeniser, against roughly 750,000 on the old one.

The cost-saving routing pattern

Build a Haiku-driven router as the first agent in the chain. It classifies incoming requests by type and difficulty, then dispatches to: a Haiku agent for simple cases, a Sonnet agent for the default case, and an Opus agent only for the genuinely hard ones. On current rates the spread that makes this worth building is wide — Haiku 5.5 input is 1/40th of Opus 5.5 and 1/100th of Fable 5.1. The Anthropic Agent SDK's sub-agent pattern fits this routing model directly. Two cautions: caches are model-scoped, so a cascade forfeits cache reuse across its tiers, and the cheaper request that needs three turns to finish the job is not cheaper. Measure cost per completed task, not per call.

05 · Decision guide

When Claude is the right model. When it isn't.

Use Claude when

  • Instruction-following reliability is load-bearing — the model has to do exactly what you ask
  • Long-context reasoning matters — 1M-token windows with real use of the context, now on every tier
  • You want extended thinking for hard reasoning steps
  • You're building production agents that need auditable behaviour
  • MCP-native tool integration is a feature you want
  • Computer-use or vision-heavy workflows where Claude leads
  • You're already standardised on Claude (most SA enterprise that's picked one frontier model)

Skip Claude when

  • POPIA / data-residency forbids cross-border to US (Bedrock af-south-1 doesn’t solve this — Claude inference still routes globally)
  • Cost-sensitive at extreme scale — open-weights via Ollama is cheaper
  • You need context beyond 1M tokens — Claude ships 1M across the current lineup, but Gemini Pro / Ultra still leads past that
  • Voice / video native — Gemini Live or specialised voice APIs
  • DALL-E or specialised image-gen integration — OpenAI ecosystem fits
  • You want a fully open / self-hostable model — Claude is closed
  • Your workload needs a hard per-request token ceiling on thinking — budget_tokens is gone on the current lineup, and effort is a dial, not a cap
06 · South African context

Where Claude lands in SA delivery work.

Enterprise · AWS Bedrock af-south-1: local endpoint, global inference

For SA enterprise (banks, insurers, telcos) on AWS, Bedrock in Cape Town gives you a local endpoint for Claude, with CloudWatch and CloudTrail logs in-region and IAM controls that fit an existing AWS posture. It does not give you SA data residency: from af-south-1, Claude is available only through global cross-Region inference, so prompts are processed wherever AWS has capacity. Treat it as a POPIA Section 72 transfer, the same as the direct API, with documented cross-border consent flows. If prompts must stay in country, Claude isn't currently an option — see where LLM inference runs in SA.

Studio · the daily-driver tier

Many SA studios have made Claude the daily driver via Claude Code (the CLI), Claude Desktop, or Cursor's Claude integration. The honest reality: this site was substantially written with Claude running through Claude Code. For studio dev work where productivity-per-engineer matters more than per-token cost, Claude is hard to beat — and the SDK leaf in this domain explains how to extend that productivity into your own production agents.

FX exposure note

Claude is USD-billed. At pilot volume (single-digit thousands of requests / month), the cost is invisible. At production volume, it's a real line item, and the rand leg of it moves without warning. Mitigations that work in practice: (a) the Haiku router pattern in the previous section, (b) prompt caching for RAG agents — cache reads are 5% of base input on Opus 5.5 and Sonnet 5.5, the largest single lever most teams have, (c) the Batch API for nightly workloads, (d) hybrid local+cloud where Ollama-Gemma handles the work that doesn't need frontier reasoning. Most SA studios that run Claude in production end up with all four in place. Budget in tokens, not in rands, and re-baseline the token counts whenever you change model generation — see the tokeniser note above.
